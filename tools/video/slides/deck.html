Why now

AI-written tests fail silently.

A test derived from the implementation cannot disagree with the implementation. If the code has a bug, the test records that bug as the expected value and reports green.
  • About a quarter of merged commits in 2026 carry AI traces. The agent writes the tests too.
  • Coverage measures whether a line ran. It cannot measure whether a test could have failed.
  • The only way to find out is to break the code on purpose and see whether anything screams.

AI technologies used

Reviewer, not author.

  • Claude Sonnet via OpenRouter, strict JSON schema output.
  • Two-step verification: the proposed test must pass on the original and fail on the mutant before anyone sees it.
  • A proposal citing a mutant id not in the run is rejected before execution.
  • Every call logged: tokens, cost, latency. About $0.015 per proposal.
The model never computes the score.
The model never marks a mutant killed.
The model never edits the code under test.
A test is shown only after our runner proves it.

On the demo repo: 10 proposals, 9 verified kills, 1 rejected because it failed on the original code. The rejection is the product working.
