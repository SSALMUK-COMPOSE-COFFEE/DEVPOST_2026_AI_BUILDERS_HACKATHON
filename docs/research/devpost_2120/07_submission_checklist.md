## 3. 영상 요건 (실격 리스크 1순위)

| 항목 | 규정 원문 | 실행 |
| --- | --- | --- |
| 길이 | 메인 `a video of up to 5 minutes` / 규정 `3–5 minutes recommended` | **4분 40초 목표. 5분 절대 초과 금지** |
| 공개 | (명시 없음) | YouTube 공개 또는 일부공개. 비공개 금지 |
| 필수 내용 | 아래 5개 | 순서대로 커버 |

규정이 요구하는 5요소 원문:
> • The problem being solved
> • How the solution works
> • Key features and functionality
> • **The role of AI within the product**
> • **A live demonstration of the product in action**

### 4분 40초 구성표

| 시각 | 내용 | 비중 대응 |
| --- | --- | --- |
| 0:00 ~ 0:20 | **숫자 한 문장으로 시작.** "커버리지는 94%였습니다. 실제로 잡히는 버그는 3분의 1이었습니다." 슬라이드 없이 화면부터 | 심사위원이 끝까지 볼지가 여기서 결정됨 |
| 0:20 ~ 0:50 | 문제. 누가, 언제, 얼마나 아픈가 | Impact 25% |
| 0:50 ~ 2:50 | **라이브 시연 (2분).** 실제 화면, 실제 입력, 실제 결과. 편집으로 대기시간만 잘라냄 | Presentation 15% + UX 15% |
| 2:50 ~ 3:40 | 동작 원리 + **AI의 역할**. 아키텍처 다이어그램 1장. "판정은 결정론적이고, LLM은 설명과 수정 제안만 합니다" | Technical 25% + Innovation 20% |
| 3:40 ~ 4:20 | 정량 수치 3개 + 요금제 화면 (SaaS 시그널) | Impact + Best SaaS 조준 |
| 4:20 ~ 4:40 | 로드맵 1줄 + 라이브 URL 화면에 크게 + **"I would use this tomorrow"** 를 겨냥한 마무리 | 테마 원문 직격 |

### 절대 하지 말 것

주최측이 명시적으로 배제한 것:
> `We are not looking for pitch decks, concept videos, or AI wrappers with minimal differentiation.`

- ❌ 슬라이드만 넘기는 영상
- ❌ 목업 화면, 가짜 데이터가 들어간 대시보드
- ❌ 트랜지션, 배경음악 볼륨, 인트로 애니메이션 (시간 낭비이자 감점)
- ✅ 자막은 필수. 심사위원 20명 중 다수가 비영어권이고 음소거로 볼 수 있습니다

## 4. 덱 10장 (섹션 제목을 규정 문구 그대로)

규정이 8개 섹션을 지정했습니다. **슬라이드 제목을 이 영어 문구 그대로 쓰십시오.** 심사위원이 체크리스트로 대조합니다.

| # | 제목 | 내용 |
| --- | --- | --- |
| 1 | (타이틀) | 제품명 + 숫자가 든 한 줄 + 라이브 URL |
| 2 | **Problem Statement** | 누가 언제 얼마나 아픈가. 숫자 1개 |
| 3 | **Solution Overview** | 한 문장 + 스크린샷 1장 |
| 4 | **Target Users** | 구체적 직함 3개. "개발자" 말고 "CI를 관리하는 시니어 백엔드" |
| 5 | **Product Features** | 4개. 각 1줄 |
| 6 | **Technical Architecture** | 다이어그램 + **확장성·성능·보안·테스트 한 줄씩** (규정 페이지의 `Scalability and feasibility` 직격) |
| 7 | **AI Technologies Used** | 어떤 모델을 어디에 왜. 멀티 프로바이더 폴백 그래프 |
| 8 | **Impact and Value Proposition** | **정량 수치 3개** |
| 9 | **Future Roadmap** | 3단계. 창업 의지 한 줄 (NexFellow Founder's Choice 조준) |
| 10 | (마무리) | 라이브 URL + 레포 URL + 데모 계정 정보 |

> 업로드 위치는 **미확인**입니다(포럼 질문 2건 미응답). **레포에 `deck.pdf` 커밋 + Devpost 설명 상단에 링크**를 기본으로 하고, 폼에 업로드 필드가 보이면 병행하십시오.

## 6. 최종 검증 체크리스트 (09:15 ~ 09:45)

### 실격 방지 (하나라도 ❌면 수상 불가)

- [ ] 레포가 **public** 인가. 시크릿 창에서 로그아웃 상태로 열어볼 것
- [ ] 영상 길이가 **5분 이하**인가. YouTube에 표시된 길이로 확인
- [ ] 영상이 **비공개가 아닌가**. 시크릿 창에서 재생될 것
- [ ] 영상에 **실제 제품이 동작하는 장면**이 있는가 (`A live demonstration of the product in action`)
- [ ] 라이브 URL이 **시크릿 창에서, 로그인 없이** 열리는가
- [ ] Discord 가입 + `#introductions` 자기소개 완료
- [ ] 팀원이 있다면 전원 Devpost 계정 생성 + 각자 Register 완료, 이메일이 계정 이메일과 일치
- [ ] 회사 이메일/회사 이름으로 제출하지 않았는가 (`Companies/professional organizations excluded`)

### 점수 확보

- [ ] 태그라인에 **숫자**가 있는가
- [ ] 영상 첫 20초에 **숫자 한 문장**이 나오는가
- [ ] 아키텍처 다이어그램 1장이 레포와 덱 양쪽에 있는가
- [ ] **정량 수치 3개**가 덱 8번 슬라이드와 Devpost 본문에 있는가
- [ ] 요금제 페이지가 존재하는가 (Best SaaS 시그널). 가짜 결제 버튼은 없는가
- [ ] 아키텍처 슬라이드에 확장성·성능·보안·테스트가 한 줄씩 있는가 (`Scalability and feasibility`)
- [ ] `HACKATHON.md` 에 해커톤 기간 제작 범위가 명시되어 있는가
- [ ] 덱 PDF가 레포에 있고 Devpost 본문 상단에 링크되어 있는가
- [ ] README에 **데모 계정 정보**가 있는가 (심사위원이 로그인해볼 수 있게)
- [ ] 스크린샷 3~5장 업로드, 첫 장이 가장 강한 화면인가

### 심사 기간 대비 (9/16 22:00 ~ 9/21 10:00 KST)

- [ ] 서버가 5일간 살아 있도록 systemd 재시작 정책 설정
- [ ] TLS 인증서 만료일이 5일 이후인지 확인
- [ ] LLM API 크레딧 잔액 확인. 심사위원 20명 × 수 회 호출을 감당할 것
- [ ] 레이트리밋 또는 데모 모드 상한 설정 (누군가 API 비용을 태우지 않도록)

## 7. 만약 시간이 부족해진다면 (우선순위)

상황이 나빠질 때 **버리는 순서**입니다. 위에서부터 버리십시오.

1. i18n / 다크모드 / 애니메이션
2. 대시보드 히스토리 화면
3. 로그인 기능 (게스트 모드만 남김. 단 로그인 **화면**은 남겨 SaaS로 보이게)
4. 멀티 프로바이더 폴백
5. 덱 10장 → 8장
6. 영상 자막

**절대 버리면 안 되는 것 5개**: 라이브 URL · public 레포 · 5분 이하 영상 · 정량 수치 3개 · Devpost 폼 저장.

> 이 5개만 있으면 제출은 성립합니다. 나머지는 전부 점수의 문제이지 자격의 문제가 아닙니다.
> **완벽한 미제출보다 불완전한 제출이 무한히 낫습니다.**
